阅读指南：先有一条轻松的路线

预计 8 分钟 · 目标：知道要准备什么，遇到问题从哪里查

虚拟机（Virtual Machine，VM）是软件模拟出来的一台电脑。你可以把练习放在里面，但它仍会占用真电脑的内存（Memory）和硬盘（Disk），也会访问你允许它访问的网络、文件。先用自己的练习资料，不把唯一一份重要文件放进去。

① 准备好认识虚拟机与安装软件第 0–3 章 · 约 53 分钟
② 装起来创建 Ubuntu 并装好 Tools第 4–6 章 · 约 105 分钟
③ 敢尝试快照、迁移、扩容、网络第 7–10 章 · 约 90 分钟
④ 自己完成处理报错并做综合实战第 11–12 章 · 约 60 分钟

第一次通读与实操约 5 小时，可分 3–4 次完成；下载、系统更新和 Win11 分支另计。章节按你的任务列为 0–12，共 13 个编号章节。

动手前的清单

卡住时，先做这四件小事

  1. 确认你在哪台电脑。能看到 VMware 菜单的是宿主机窗口；里面的 Ubuntu/Win11 桌面是客户机。
  2. 保存报错原文。记下完整句子、操作步骤、软件小版本、虚拟机是否开机；不要连续乱点十种“修复”。
  3. 按层找原因。软件装不上看第 2 章；系统装不上看第 5 章；网络问题看第 10 章；紧急情况看第 11 章。
  4. 一次只改一个地方。记下原值，重试一次，确认有效后再继续。运行中的虚拟机先在客户机里正常关机。
你随时可以暂停：鼠标出不来就按 Ctrl + Alt。它只释放输入，不会删除或关闭虚拟机。
01

概念与授权：先认清谁是谁

预计 10 分钟 · 目标：选对产品，知道免费覆盖什么

宿主机 Host

你眼前这台真实的 Windows 电脑。它提供 CPU、内存、硬盘和网络。关掉宿主机，里面的虚拟机也无法继续工作。

客户机 Guest

虚拟机里面安装的操作系统。主线是 Ubuntu Linux，分支是 Windows 11。它有自己的账户、桌面、更新和虚拟硬盘。

虚拟化管理程序（Hypervisor）负责把真机资源分给虚拟机。给客户机 4GB 内存，意味着运行时真机要拿出相应资源；虚拟磁盘设置 40GB，通常是容量上限，按需增长的磁盘不会立刻占满 40GB。

这些名字怎么选
产品在哪里运行你需要知道的区别
Workstation ProWindows / Linux 桌面本教程使用的完整桌面产品，提供快照、克隆、虚拟网络编辑器。
Workstation PlayerWindows / Linux 桌面历史上的精简桌面产品。旧教程里的 Player 不具备 Pro 的完整管理功能；新学习直接选择 Pro。
FusionmacOSMac 用户的桌面虚拟化产品。Apple 芯片使用 ARM 客户机，本教程的 x86-64 镜像与菜单不直接套用。
ESXi直接装到受支持的服务器硬件裸机型（Bare-metal）虚拟化平台，常用浏览器管理；不是在 Windows 里双击运行的 Workstation。

17.x 的授权，别再找“激活码”了

截至核实日，Broadcom 的下载授权说明写明：Workstation Pro 对个人、教育和商业用途免费；该免费版本政策适用于 17.5.2 及以上，无需许可证密钥。更早的 17.x 下载可能仍要求历史授权。免费使用仍须遵守许可条款，Windows 客户机本身的授权另算。

部分旧安装器仍显示“个人用途”或许可证页面，新安装器的结束流程又可能不同。按你安装包提供的免费选项或“完成”继续；如果只有试用倒计时，先核对小版本和官方说明。不要输入来源不明的密钥，也不要用破解补丁。

版本与政策的边界：17.5.2 是免费政策的起点，不是本教程对“最新安全版本”的推荐。下载时查看官方现行发布说明、兼容表和安全公告；若 17.x 已不满足当前安全或系统要求，优先采用官方支持版本，菜单再对照本教程。免费许可不等于所有版本都持续有更新或人工支持。

02

下载安装：让真电脑先准备好

预计 25 分钟，不含下载 · 目标：软件可启动，虚拟化可用

官方最低要求与舒服的练习配置

官方 17.x 资料列出的基础门槛包括：兼容的 64 位 x86/AMD64 处理器，通常为 2011 年或之后的受支持型号，Intel VT-x 或 AMD-V；最低 2GB 内存、推荐至少 4GB；应用安装约需 2.5GB 空间。这是软件门槛，不是“宿主机 + 客户机”同时流畅的保证。CPU 例外与小版本兼容性以官方列表为准。

这份课建议真机至少 16GB 内存、4 核级 CPU、SSD；8GB 真机可以尝试轻量 Ubuntu 单机练习，但不要同时打开很多程序。Win11 客户机要求更高，去第 9 章计算再分配。Windows on ARM 不属于本教程的 x86-64 宿主机场景。

依据：S4 官方基础系统要求S2 Windows 10/11 宿主机支持

VT-x / AMD-V 与 Hyper-V / VBS 是两件事

  1. 先看 CPU 虚拟化开关

    按 Ctrl + Shift + Esc 打开任务管理器 → 性能 → CPU。看到“虚拟化：已启用”即可继续；禁用则按电脑厂商手册进入 UEFI/BIOS，找 Intel Virtualization Technology / VT-x 或 SVM Mode / AMD-V 并启用，保存后重启。不要把 VT-d/IOMMU 当成 VT-x。

  2. 再认识 Windows 的虚拟化功能

    Hyper-V 是微软的虚拟化平台；基于虚拟化的安全性（Virtualization-based Security，VBS）可能使用它。Windows Hypervisor Platform（WHP）让兼容的 Workstation 与它们共存。Workstation 15.5.5 以后具备这条路径；实际性能、嵌套虚拟化与兼容性仍取决于 CPU、Windows 构建和补丁。

  3. 先尝试兼容路线，再决定是否改安全设置

    更新到官方兼容的 Windows 与 Workstation 补丁，按安装器提示配置 WHP。不要为了“可能更快”直接关闭内存完整性或 Credential Guard。如果确实遇到兼容报错，先看第 11 章；关闭 Hyper-V/VBS 可能影响 WSL2、Docker、沙盒和安全防护，公司设备交给管理员处理。

依据：S5 Hyper-V / VBS 共存条件

从官方下载到打开安装器

  1. 联网时在浏览器输入文末 S1 的官方地址，登录或注册 Broadcom Support Portal 账户。进入官方免费软件下载入口，找到 VMware Workstation Pro 的 Windows 下载。
  2. 本教程对应 17.x。按官方可用的分支和补丁选择，核对 Windows 平台、文件名、版本和支持范围。账号资料与贸易合规表按真实情况填写；遇到审核等待，按官网流程处理。
  3. 文件下载完成后，右键安装包 → 属性 → 数字签名，检查签名状态有效；如下载页提供校验值，可以比对。签名主体以该官方包为准，不凭文件名判断真假。
  4. 关闭正在运行的虚拟机和相关应用，再启动安装器。Windows 账户控制提示要与刚刚打开的官方安装包相符。

安装向导逐屏：每一页都知道怎么选

下面按 17.x Windows 安装器的常见顺序列出完整决策。某些页仅在特定补丁版或宿主机条件下出现；按钮文字以你所装版本为准。安装页用文字逐屏说明，不伪造未核实的官方屏幕。

1 / 欢迎使用安装向导

选什么：下一步。为什么：开始安装应用。选错会怎样：取消只退出安装器，还没创建任何虚拟机。

2 / 最终用户许可协议

选什么：阅读并在同意后接受。为什么：免费也受许可条款约束。选错会怎样：不同意则不能继续；不要把接受 Workstation 条款当作获得 Windows 授权。

3 / 兼容性或 WHP 提示（条件页）

选什么：若检测到 Hyper-V/VBS 并提示安装 WHP，按该版本官方说明启用所需兼容组件，记录是否需要重启。为什么：让两套虚拟化技术通过支持路径协作。选错会怎样：可能装好软件却无法启动客户机；不要边装边随意关安全功能。

4 / 自定义安装

选什么：程序路径用默认即可；出现“增强型键盘驱动程序”时，普通入门可不选，确有特殊按键需求再选；PATH 选项通常保留安装器默认。为什么：虚拟机存储路径稍后单独设置。选错会怎样：增强驱动可能要求重启，PATH 主要影响命令行工具，不决定虚拟机磁盘放在哪里。17.6 已移除增强型键盘驱动，没有该选项时直接继续。

5 / 用户体验设置

选什么：产品更新检查按联网条件保留；客户体验改进计划按你的隐私偏好选择。为什么：两者与能否创建虚拟机无直接关系。选错会怎样：不会损坏客户机，后续可在首选项中调整。

6 / 快捷方式

选什么：保留桌面和开始菜单入口。为什么：初学时容易找到程序。选错会怎样：没快捷方式也能从开始菜单搜索，不需要重新安装系统。

7 / 已准备好安装 → 安装

选什么：确认目录后安装并等待。为什么：这一步会安装驱动和虚拟网卡，网络可能短暂变化。选错会怎样：中途强行断电可能留下未完成的驱动；若失败记录错误，重启后再修复。

8 / 完成、许可证与重启

选什么：依 S1 的免费流程完成；出现“许可证”按钮不代表必须购买。需要重启时保存工作再重启。首次运行的免费选项按实际版本选择。为什么：驱动重启后才完整生效。选错会怎样：许可证或版本不对应时可能仍显示试用；回到 S1 核对，不找注册码。

到这里就算成功：开始菜单能打开 VMware Workstation Pro；帮助 → 关于 VMware Workstation 能看到实际 17.x 小版本；任务管理器显示虚拟化已启用。截图/记下版本，后续排错会用到。

04

新建虚拟机：先搭一台“空电脑”

预计 20 分钟 · 目标：创建可检查、可修改的虚拟硬件

主线用 Ubuntu Desktop 22.04 LTS 的 64 位 x86 镜像作为教学实例，系统安装页随镜像更新会变化。你也可以选当前受支持的 Ubuntu LTS，但应先核对所用 Workstation 小版本的客户机兼容性。本页不会下载镜像或真的创建虚拟机。

新建向导练习

交互 2 / 下一步模拟器

这个组件在教你什么：练习每一步的选择和后果。两条路线可切换；切换路线或重置会清空本组件的选择。

Ubuntu 路线：典型 → 稍后安装操作系统 → Linux / Ubuntu 64 位 → 名称与位置 → 40GB 可增长磁盘、拆分为多个文件 → 自定义硬件 → 完成。Win11 路线：典型 → 稍后安装 → Microsoft Windows / Windows 11 x64 → 名称与位置 → 按出现的页面配置加密并保存密码 → 至少 64GB 磁盘（教学建议 80GB）→ 检查 UEFI / Secure Boot / vTPM → 完成。

为什么建议“稍后安装操作系统”

这一步只是先不把 ISO 交给自动安装流程，不代表不安装系统。先生成空虚拟机，你就能检查内存、CPU、网卡、UEFI 和 Win11 的 vTPM，再手动挂载 ISO。这样能看懂系统安装器，也避免自动安装（Easy Install）替你填写用户名、分区或其他参数后，让你不知道出了什么事。

如果一开始已选 ISO 并触发简易安装，不必慌：未装好系统时可以退出向导重新新建空机。不要为了跳过自动流程去删未知文件。已经安装成功且账户和磁盘符合预期，也不需要重装。

创建后的硬件复查

  • 内存 / 处理器：用第 9 章计算器，通常从 Ubuntu 2 vCPU / 4GB、Win11 2 vCPU / 8GB 开始；真机资源不足时先减少后台负载。处理器常用 1 个处理器 × 2 个核心，二者乘积才是总 vCPU。
  • 网络适配器：NAT；勾选“启动时连接”。学习普通系统安装，不需要启用“虚拟化 Intel VT-x/EPT 或 AMD-V/RVI”等嵌套虚拟化选项。
  • CD/DVD：使用 ISO 映像文件，浏览到官方镜像；勾选“启动时连接”。ISO 留在稳定路径，不要从下载临时目录移走。
  • 硬盘：新建虚拟磁盘，采用向导为该系统推荐的控制器。不要选“使用物理磁盘”，以免接触真实磁盘。
  • Win11：开机前完成下一章的 UEFI、安全启动、加密与 vTPM 检查。不要先安装再随意切 BIOS/UEFI，否则可能无法启动。
成功检查：左侧库有“Ubuntu-Lab”，状态为已关闭；设置里能找到 CPU、内存、硬盘、CD/DVD 和网络适配器。还没进入系统，是正常的。
05

装系统：看到熟悉的桌面

预计 60 分钟，Win11 另计约 45 分钟 · 目标：系统可启动、可正常关机

Ubuntu 完整流程

  1. 拿到正确的 ISO

    从 Ubuntu 官方下载入口获取 Desktop、amd64/x86-64 镜像；amd64 也适用于兼容 Intel 64 位 CPU。不要拿 ARM64 镜像放到这条 x86-64 路线。按官网校验说明核对下载完整性。

  2. 挂载 ISO，开机

    关机状态 → 虚拟机 → 设置 → CD/DVD → 使用 ISO 映像文件 → 浏览 → 启动时连接。开启虚拟机，出现启动选择时选 Try or Install Ubuntu（试用或安装 Ubuntu）。若进了网络启动或找不到系统，先查光驱是否连接。

  3. 选择安装与语言、键盘

    进入桌面安装器，选择安装 Ubuntu（Install Ubuntu），语言选简体中文，键盘按真实布局选。默认普通英文键盘通常可输入英文与数字；先在测试框试打一次。安装器的具体分屏随镜像版本变化。

  4. 网络、软件与更新

    NAT 连网后可下载更新；网络慢时先完成基础安装，进桌面再更新。按实际安装器选择默认/正常安装即可；极简安装软件少，但不是坏了。第三方驱动与媒体支持按需要选择，虚拟机里通常不需要给它安装真机显卡驱动。

  5. 分区：只确认“虚拟硬盘”

    对刚建的空虚拟机，可选“擦除磁盘并安装 Ubuntu”。确认目标容量与第 4 章虚拟磁盘一致，且没有映射物理磁盘。这句话会擦除所选客户机磁盘里的资料；如果虚拟机已有重要数据，先停止并备份。初学路线使用默认分区；第 9 章会教你先识别分区再扩容。

  6. 时区、账户与密码

    时区按你所在地选择；示例账户用 student，主机名用 ubuntu-lab。设置自己的密码并保存，登录密码也是执行 sudo 管理操作时需要的密码。不要照抄示例密码。

  7. 安装完成后重启并移除安装介质

    按安装器提示重启。提示移除介质时，在 VMware 的 CD/DVD 菜单断开 ISO，再回到客户机按 Enter。若重启又回到安装页，先断开 ISO，启动已安装磁盘，不要重新分区。

  8. 首次进入桌面，更新与确认

共享文件夹：宿主机设置 → 客户机访问

    例如 D:\VM-Share，没有 D 盘则选用户目录。放入 hello.txt 测试文件；别把整个 C 盘、桌面或隐私目录直接共享。

SMB 与 SSH：独立于 VMware 的网络方式

SMB（Server Message Block，服务器消息块）：宿主机专门的文件夹 → 属性 → 共享 → 高级共享，指定共享名和有权限的账户；同时核对“安全”页 NTFS 权限。只在可信私有网络启用文件和打印机共享，保留密码保护。Windows 客户机输入 \\宿主机IP\共享名；Ubuntu 文件管理器“其他位置 → 连接到服务器”输入 smb://宿主机IP/共享名。NAT 下优先使用宿主机 VMnet8 网卡的实际 IPv4 地址，不要猜它必然是 .1；防火墙仅放行需要的来源，不开启过时 SMB1。

SSH（Secure Shell，安全外壳）/ SFTP（SSH File Transfer Protocol，SSH 文件传输协议）：Ubuntu 装好 OpenSSH 服务，Windows 用自带 OpenSSH 客户端或可信 SFTP 客户端连接。NAT 下宿主机通常能直接访问客户机 IP；练习端口转发时跟第 10、12 章做。

scp -P 2222 .\hello.txt student@127.0.0.1:/home/student/

scp 的端口参数是大写 -P；ssh 是小写 -p。文件名、用户名和目标目录按你实际环境改。执行前保证当前目录里真的有 hello.txt；没有 scp/ssh 时，在 Windows 可选功能中安装 OpenSSH 客户端。

    文件是什么 / 你该怎么对待它
    .vmx虚拟机配置：硬件、磁盘路径等。打开虚拟机一般选它；先备份再编辑，不把它当虚拟硬盘。

    方法 A：关机后复制整个文件夹

    1. 正常关机，不是挂起

      客户机内部关机，确认状态为已关闭；退出 Workstation 并确认该虚拟机不再运行。挂起会留下内存状态，不适合跨硬件迁移。

    2. 检查依赖并备份

      确认所有虚拟磁盘、快照文件都在计划复制范围内。链接克隆、存放在文件夹外的磁盘和共享文件夹不会自动被完整复制；必要时先做完整克隆。加密机保存 VMware 加密密码和 Windows 恢复密钥。

    3. 整体复制，保持内部文件名

      将完整文件夹复制到目标电脑，等待传输完成。不要逐个挑文件，也不要复制运行中不断变化的磁盘。目标磁盘应支持大文件，避免 FAT32 的单文件限制。

    4. 目标电脑打开 .vmx

      在兼容的 Workstation 里“文件 → 打开”。若询问“我已移动该虚拟机 / 我已复制该虚拟机”：搬家且原机不会再运行时选已移动；保留原机并新增一台时选已复制，让 Workstation 生成新的身份和 MAC。

    5. 先验证，再处理原副本

      检查磁盘、快照、网络、共享路径、加密与系统激活。迁移验证完成以前保留原副本。不要让两台有重复静态 IP 或机器名的系统同时连入同一网络。

    方法 B：OVF / OVA 导出与导入

    开放虚拟化格式（Open Virtualization Format，OVF）描述虚拟硬件与磁盘，通常是一组文件；开放虚拟化归档（Open Virtual Appliance，OVA）把它们打包为单文件。它们适合交换“可部署的虚拟机”，不是原样保存快照树、加密身份和所有宿主机设置的备份格式。

    1. 导出 OVF：关闭虚拟机，选中它 → 文件 → 导出为 OVF，保存到新文件夹，保留输出的所有相关文件。具体入口可用性以 17.x 实际安装为准。
    2. 需要 OVA：可使用 VMware OVF Tool，将已导出的 OVF 转为 OVA。示例命令只适用于工具安装在示例路径的情况，先核对 ovftool.exe 确实存在。
    3. 导入：文件 → 打开 → 选择 .ovf 或 .ova → 设置名称和存储位置 → 导入。若出现 OVF 规范/硬件兼容错误，先核对目标版本与导出设置；不要无脑忽视兼容警告。
    4. 复查：CPU、内存、网卡模式、固件、磁盘控制器和 Tools 都要再确认。MAC 变化后客户机网络配置可能需要更新。

  'D:\Export\Ubuntu-Lab.ovf' `

    虚拟磁盘扩容有两步，缺一不可

    第 1 步把“虚拟硬盘”变大；第 2 步把客户机里的分区和文件系统变大。只做第 1 步，Windows 的 C 盘或 Ubuntu 根目录容量可能完全不变。这是正常现象，不是扩容失败。

    1. 先关机备份，再确认快照与空间

      关机后做独立备份。普通扩容要求磁盘没有快照链等阻碍；需要删除快照时使用快照管理器并等待合并，宿主机必须留足临时工作空间。带链接克隆依赖、加密限制或共享磁盘的环境先查官方说明。不要凭一个“扩展”按钮灰色就去删 vmdk。

    2. 在 Workstation 图形界面扩容

      虚拟机 → 设置 → 硬盘 → 实用工具 / 扩展（具体按钮位置以版本为准），例如从 40GB 改成 60GB。这里填的是新总容量，不是增加量。等待完成再启动客户机。此操作不能当作无损缩盘工具。

    Windows 客户机：磁盘管理

    在客户机中右键开始菜单 → 磁盘管理。找到变大后的同一磁盘；若 C 盘右侧紧邻“未分配”空间，右键 C 盘 → 扩展卷 → 按向导添加容量。若中间隔着恢复分区，扩展卷可能变灰：不要删除恢复分区来碰运气。可将空闲空间建成新数据卷，或在完整备份后按微软/分区工具文档调整布局。BitLocker 场景先确保恢复密钥可用，并按工具要求处理保护状态。

    网络与外设：先用 NAT，再理解它

    预计 25 分钟 · 目标：看懂数据去哪里，按顺序排查

    新手默认用 NAT。网络地址转换（Network Address Translation，NAT）让虚拟机通过宿主机的外网连接访问网络，通常最省事。DHCP（Dynamic Host Configuration Protocol，动态主机配置协议）负责自动分配 IP；DNS（Domain Name System，域名系统）把网站名字转换为地址。能拿到 IP 不等于 DNS 和上网都正常。

    让一个数据包走一遍

    交互 4 / 网络路径

    这个组件在教你什么：比较三种模式的边界。播放只走一遍，不循环；“减少动态效果”开启时改成静态分步高亮。图是网络关系示意，不是 VMware 窗口。

    NAT：客户机 → VMnet8 私网 → 宿主机上的 NAT 服务 → 物理网络/互联网；外部主动访问通常要端口转发。桥接：客户机 → VMnet0 桥接 → 宿主机物理网卡 → 局域网路由器/其他设备；客户机是局域网独立节点。仅主机：客户机 → VMnet1 私网 → 宿主机与同网络虚拟机；默认不通往互联网。均不等于防恶意软件沙箱。

    NAT 端口转发：把宿主机 2222 交给客户机 22

    端口（Port）可以看成服务的门牌号。SSH 常用 TCP 22。教程把宿主机 TCP 2222 转给 Ubuntu TCP 22；2222 只是示例，选一个未被占用的端口。

    1. 客户机选 NAT，启动 Ubuntu，确保已安装并启动 SSH 服务。按第 12 章读取实际 IPv4 地址，先从宿主机直接连客户机 IP 验证服务。
    2. 宿主机 Workstation → 编辑 → 虚拟网络编辑器 → 更改设置（需要管理员权限）→ VMnet8 → NAT 设置 → 添加端口转发。
    3. 填写：主机端口 2222、类型 TCP、虚拟机 IP 为刚查到的实际值、虚拟机端口 22、描述 Ubuntu SSH，确定并应用。
    4. 宿主机运行 ssh -p 2222 student@127.0.0.1。仅自己使用也要检查宿主机防火墙：转发服务可能监听多个接口，连接 127.0.0.1 不等于监听范围仅限本机；不要为方便放行所有来源或开放路由器公网转发。
    5. 客户机 DHCP 地址变化后，旧转发会指向错误地址。先重新查 IP 并更新规则；需要长期固定时按网络规划选择 DHCP 保留或不冲突的静态配置，别随便把动态池内的地址写死。

    宿主机连 NAT 客户机通常不必转发；这里专门练习转发机制。局域网其他设备连接的是“宿主机局域网 IP:2222”，还需宿主机防火墙仅对可信来源开放。不要将 127.0.0.1 填给另一台电脑，那会指向那台电脑自己。

    三个典型场景：照着顺序查

    场景 A：客户机打不开网页
    1. 先确认宿主机本身能上网；VPN、代理或公司策略可能影响虚拟网络。
    2. 客户机网卡选择 NAT，确认“已连接 / 启动时连接”，再看客户机是否拿到 IP、默认网关。
    3. Ubuntu 用 ip -br addr、ip route；Windows 客户机用 ipconfig /all。出现 169.254.x.x 常提示没有获得有效 DHCP 配置。
    4. 先测试实际网关可达，再检查 DNS（例如 Ubuntu resolvectl status）。ping 失败不能单独证明断网，网络可能禁 ICMP。
    5. 再看宿主机 VMware NAT Service / DHCP Service 是否正常；记录设置后按官方排障。不要第一步就“还原默认设置”，它会改掉自定义网络和转发。
    场景 B：桥接后拿不到局域网地址
    1. 确认宿主机当前用的是 Wi-Fi 还是有线；在虚拟网络编辑器把 VMnet0 桥接到实际联网网卡。
    2. 确认该局域网允许额外设备与 MAC；访客网、校园认证、企业准入和无线 AP 可能限制桥接。
    3. 让客户机重新获取 DHCP 地址，核对同网段、掩码、网关；不要复制宿主机的同一个 IP。
    4. 仍受网络限制时改回 NAT 完成学习；真有局域网服务需求再与网络管理员确认。
    场景 C：SSH 端口转发连接失败
    1. 在 Ubuntu 本机检查 SSH 服务和 22 端口监听，先确认服务存在。
    2. 宿主机直接连接“客户机 IP:22”。若失败，先查客户机 IP、网卡与防火墙，不急着改转发。
    3. 核对 VMnet8 的 TCP 2222 → 正确客户机 IP → 22，检查宿主机 2222 是否已被其他程序占用。
    4. 测试宿主机 127.0.0.1:2222；本机可用而局域网不可用，再查宿主机防火墙的来源范围、网络配置文件与网络隔离。
    5. “Connection refused”偏向未监听/主动拒绝；超时偏向路径/过滤；认证失败说明网络已到服务，应该查账户和密钥。

    USB 与打印机

    USB 直通（USB Passthrough）：插入设备，在“虚拟机 → 可移动设备 → 对应 USB 设备 → 连接（断开与主机的连接）”切换归属。一个设备通常不能同时给宿主机和客户机独占使用。U 盘先安全弹出，写入时不要切换；键盘鼠标不要随意直通，否则可能暂时失去宿主机控制。

    识别失败时，先看宿主机是否识别、客户机是否有驱动，再检查 USB 控制器兼容版本、VMware USB Arbitration Service 和是否被其他软件占用。不要用关闭安全软件作为第一步。

    打印机：17.x 的旧“虚拟打印机”可用性取决于小版本；若设置中没有该功能，不必寻找“启用虚拟打印机”的旧教程。历史 17.5 发布说明当前未能重新打开核验，移除版本请以官方最新信息为准。选客户机支持的 USB 打印机直通，或按打印机实际 IP 在客户机添加网络打印机并安装驱动；NAT 能访问网络打印机不代表自动发现一定成功。最省心的临时方式是客户机输出 PDF，再共享到宿主机打印。

    急救包：先稳住，再处理

    预计 15 分钟 · 目标：不盲删、不乱关安全功能，按证据恢复

    报错不等于整台电脑坏了。先释放鼠标、记下原文、确认宿主机还是客户机出问题，再展开对应条目。下列操作没有效果时，保留日志和已尝试步骤，比重复安装十次更有用。

    01 · 提示 VT-x / AMD-V 未启用

    先查：任务管理器虚拟化状态、CPU 是否受支持、是否刚改 BIOS 却没有完整重启。按厂商手册启用 VT-x / SVM 并保存，不随意修改存储控制器或启动模式。

    再区分：“此平台不支持虚拟化的 Intel VT-x/EPT”可能是你给客户机勾选了嵌套虚拟化。只装普通 Ubuntu/Win11 不需要这个勾；关机后取消处理器设置中的嵌套虚拟化选项，再试。不要将它与 BIOS 里的基础虚拟化混为一谈。

    停止条件：硬件确实不受支持、固件被单位锁定，或你不确定 BIOS 选项含义时，先查厂商资料或联系管理员。

    02 · Hyper-V / Device Guard / VBS 兼容报错

    先查：Workstation 小版本、Windows 构建、是否启用 WHP，以及官方兼容条件。msinfo32 中的“基于虚拟化的安全性”状态可辅助判断；即使没有显式勾 Hyper-V，VBS 也可能在使用虚拟化平台。

    优先处理：更新兼容补丁、按官方文档修复 WHP 路线、关闭不需要的客户机嵌套虚拟化。重启一次后再测。

    确需关闭时：只有确定工作负载必须使用传统模式、理解会影响 WSL2/Docker/沙盒和安全保护，且有管理权限时，才按 S5 与当前微软文档处理 Hyper-V/VBS/内存完整性；记下原状态与恢复方法。不要运行“一键关闭全部安全功能”的脚本。

    03 · “无法锁定文件 / 虚拟机似乎正在使用”与 .lck

    先查是否真的在运行。关闭界面不代表后台客户机停止。检查 Workstation 其他窗口、任务管理器中的 vmware-vmx 进程、共享存储上的其他电脑。无法确认锁的持有者时，不动锁文件。

    1. 正常关闭所有相关客户机并退出 Workstation；有疑问时先正常重启宿主机，再确认没有虚拟机被自动启动。
    2. 确认该虚拟机既未运行也未挂起、没有别的主机访问，做一份完整文件夹备份。
    3. 仅当确定是异常退出留下的陈旧锁时，将该虚拟机目录内对应的 .lck 文件/目录移到单独临时备份位置，再打开 .vmx 测试；不要对全盘批量删除。
    4. 仍然失败就停止，按 vmware.log 的确切错误定位。不要删 .vmdk、.vmx、.nvram 或快照链来“试一下”。

    锁用来防止两处同时写磁盘；把活跃锁删除可能导致数据损坏。它不是通用清理垃圾的办法。

    04 · 鼠标被“吸进去”，回不了真电脑

    按 Ctrl + Alt 释放输入。返回桌面后再检查 Tools。若快捷键已被改过，在编辑 → 首选项 → 热键中查看实际组合。不要为抢回鼠标强制断电。

    要把 Ctrl+Alt+Delete 发给客户机，使用 Ctrl + Alt + Insert 或菜单中的发送组合键；直接按真机的 Ctrl+Alt+Delete 通常会到宿主机。

    05 · 开机黑屏、卡住或特别慢
    1. 先看状态：真机 CPU/磁盘是不是正在忙？系统首次更新或安装可能需要时间，别连续按重置。
    2. 如果提示找不到启动盘，核对 ISO 是否连接、系统是否装好、固件是否被改成另一种模式。把安装前的固件设置恢复，不要重装覆盖已有磁盘。
    3. 确认真机内存和磁盘有余量，按第 9 章减小分配；客户机 CPU 分太多也可能更慢。
    4. 图形黑屏且可正常关机时，关机后临时关闭显示设置中的 3D 加速，更新宿主机显卡驱动和匹配的 Tools，再验证。
    5. 完全无响应时，优先请求客户机正常关机。强制断电是最后手段，等同拔电源，会丢失未保存数据，并可能需要文件系统修复。记下日志后只做一次有目的的尝试。
    06 · Tools 装不上，拖放或自适应无效

    Windows：检查客户机已开机、Tools 光盘确实挂载、安装程序使用管理员权限、系统更新与重启已完成。Ubuntu：用发行版的 open-vm-tools 与 open-vm-tools-desktop，不混装旧 tar 包。查看实际安装错误，不反复运行未知安装器。

    安装成功却无法拖放时，查客户机隔离开关和 Linux 桌面会话限制；先试共享文件夹。自适应失败再查查看菜单的适应选项，不能因为拖放失败就判定整个 Tools 不工作。

    07 · 共享文件夹设置了，客户机还是找不到

    依次查：宿主目录仍存在 → 选项页共享已启用且 Share 名称正确 → Tools 服务可用 → Windows UNC 路径或 Linux HGFS 挂载正确 → 共享只读与宿主文件权限。Ubuntu 先运行 vmware-hgfsclient，再按第 6 章临时挂载。

    不要把 HGFS 与 SMB 混淆：HGFS 不需要网络发现，不应靠关闭防火墙修复。若你使用的是 SMB 路径，则按网络、账户和共享权限另查。

    08 · 磁盘空间不足，虚拟机暂停

    先分清哪一层满了：宿主机存放 .vmdk 的磁盘，还是客户机里的 C 盘/根分区？快照、挂起文件、可增长磁盘都会消耗真机空间。

    宿主机满：优先清理或移动你确认无关的宿主文件，为恢复与快照合并腾出空间；在有空间前别强行拍新快照。客户机满：清理客户机无用文件或按第 9 章扩容。不要在资源管理器删虚拟磁盘分片或差分文件；删除快照本身也可能需要额外合并空间。

    求助时可以直接复制这个信息清单：宿主机 Windows 版本与构建；Workstation 完整小版本；客户机版本；CPU/内存；虚拟机电源状态；报错原文；刚做过的改动；可用磁盘空间。日志发给别人之前检查个人信息。

    依据：S5 Hyper-V / VBSS18 磁盘空间S24 陈旧锁文件与磁盘占用S3 Workstation 排错

    综合实战：完成你的第一台实验机

    预计 45 分钟 · 目标：Ubuntu + 快照 + SSH 转发 + 共享文件夹

    这次不追求一步不差，而是每一步都有证据。先准备一台可正常上网的 Ubuntu，用户名用你自己的；下文的 student、磁盘路径和 IP 都是示例。

    1. 创建、安装、装 Tools

      依第 4、5 章建 Ubuntu，NAT 网卡，按计算器分内存，40GB 可增长磁盘。装好系统与 open-vm-tools-desktop，完成更新和重启。

      检查点：能登录，能正常关机，放大窗口后画面可适应或已知道替代显示设置。

    2. 拍下清洁基线

      关机，拍快照 01-系统与Tools就绪，然后重新开机。此后只在客户机里做练习，不修改唯一一份宿主资料。

      检查点：快照管理器能看到该节点；你能说清恢复会丢掉节点之后的客户机变化。

    3. 安装 SSH 服务，读取真实地址

      在 Ubuntu 客户机终端执行

      sudo apt update
sudo apt install openssh-server
sudo systemctl enable --now ssh
systemctl status ssh --no-pager
ss -ltn
ip -br addr
ip route
sudo ufw status

      检查点：根据真实输出确认服务在运行、TCP 22 有监听、网卡有 NAT 网段 IPv4。若 ufw 已启用且没有允许 SSH，按实际客户端来源添加 TCP 22 的最小范围规则，不要为了练习关闭整个防火墙。Ubuntu 新版本可能使用 socket 激活；服务状态与实际监听一起判断。

      仅在 UFW 已启用且需要规则时，于 Ubuntu 执行 · 把示例 IP 替换为宿主机 VMnet8 的真实 IPv4

      sudo ufw allow from 192.168.200.1 to any port 22 proto tcp

      上面的 192.168.200.1 只是规则格式示例，不是你电脑的地址。宿主机可在 ipconfig 中查 VMnet8；转发流量的源地址也需按实际观察和 NAT 设置判断，不能凭示例放行整个互联网。

    4. 先直接连，再建立转发

      在 Windows 宿主机 PowerShell 运行下方命令，把示例 192.168.200.128 换成客户机真实地址：

      在 Windows 宿主机 PowerShell 执行

      ssh student@192.168.200.128

      首次提示主机指纹时，在 Ubuntu 控制台运行下列命令比对相同算法的指纹；确认是你的机器再接受。后续指纹意外变化时先调查，不要直接删除 known_hosts。

      在 Ubuntu 客户机终端执行 · 查看 ED25519 主机指纹

      sudo ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub

      直接连接成功后输入 exit 返回宿主机。按第 10 章建立 TCP 2222 → 客户机实际 IP:22 转发，再执行：

      在 Windows 宿主机 PowerShell 执行

      ssh -p 2222 student@127.0.0.1

      检查点：可登录同一台 Ubuntu；在会话中执行 hostname 核对名字，用 exit 退出。先保留本机练习范围，不添加路由器公网转发。

    5. 建立一个只读共享，验证后再开放写入

      宿主机建 VM-Share 文件夹与 hello.txt；Workstation 添加名为 Share 的共享并先勾只读。Ubuntu 访问 /mnt/hgfs/Share，未自动挂载就走第 6 章。

      检查点：客户机能读到宿主机刚写入的内容；如果需要写入，再取消只读，并用单独测试文件验证双向可见。

    6. 保存可复现的收尾状态

      在宿主机记下客户机 IP、主机端口 2222、Share 的宿主路径和实际系统版本。关机后拍 02-SSH与共享完成；另做一份关机完整备份。宿主机的 NAT 转发表与共享原文件不在客户机快照里，迁移时要重新设置。

    关掉 Workstation 窗口，会把虚拟机一起关掉吗？

    不一定，关闭界面时可能提示后台运行、挂起或关机。最可靠的收尾是在客户机操作系统内正常关机，确认虚拟机状态为已关闭，再退出软件。

    免费 Workstation 能代替 Windows 激活吗？

    不能。虚拟化软件的许可与客户机操作系统及应用软件的许可分别计算。Windows 仍按微软条款激活，迁移或克隆也可能触发重新验证。

    为什么恢复快照后，宿主机共享里的文件没有回来？

    因为它存储在宿主机，并不属于客户机虚拟磁盘的快照范围。同样，外部服务器、网盘资料和宿主机 NAT 转发表也不会随客户机快照回退。

    今天只记住三件事，可以是哪三件？

    先用 NAT；改变系统前留返回点和独立备份；遇到问题先确认自己操作的是宿主机还是客户机。剩下的，需要时再回来查。
